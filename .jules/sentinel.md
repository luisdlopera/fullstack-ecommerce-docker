## 2025-01-20 - [Bcrypt Dummy Hash Fast-Fail Timing Attack]
**Vulnerability:** A user enumeration timing attack existed in `login.use-case.ts`. When a user was not found, the system attempted to mitigate timing attacks by hashing against a static dummy string (`$2a$12$dummyhashdummyhashdummyhashdummyhashdummyhashdummyha`).
**Learning:** Bcrypt (specifically `bcryptjs`) performs an initial structural validation of the provided hash. If the hash format (including the base64 characters of the salt) is invalid, `bcrypt.compare` fails immediately (in < 1ms), entirely bypassing the costly hashing operation. This created a significant timing difference (~100ms vs <1ms) between found and not-found users, allowing attackers to enumerate valid email addresses.
**Prevention:** Always use a structurally valid dummy hash generated by the same algorithm and work factor as the real system hashes to ensure the time taken by `bcrypt.compare` is consistent regardless of whether the user exists.
